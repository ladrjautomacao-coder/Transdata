This portal is 100% Transdata: every domain (localhost, Lovable preview/published, Vercel and any custom domain) uses the Transdata presentation. The former HopeXT brand was discontinued — never reintroduce its name, logos, colors, login screen or public signup anywhere in the project.

The Supabase project "Portal oficial - Transdata" (`emzqlctomlsjwmgthbkv`) is shared: this portal owns the `public` schema, the Transmobile app (repo `Transmobile`) lives in the `transmobile` schema and the RoadMap de Evolução (repo `roadmap-de-evolucao`) in the `roadmap` schema. The login (`auth.users`) is one list for all three. Rules:
- Migrations from this repo touch only `public` (and Transdata's own storage buckets); never alter, drop or grant on the `transmobile` or `roadmap` schemas, their buckets (`transmobile-anexos`) or their edge functions (`transmobile-*`).
- `public.handle_new_user` creates a Portal profile for every new account; Transmobile accounts (`raw_app_meta_data.sistema = 'transmobile'`) are skipped by the `transmobile_fora_do_portal` triggers on `public.profiles` and `public.user_roles`. Keep both behaviors if that function changes.
- `pgrst.db_schemas` on the `authenticator` role must keep `public, graphql_public, roadmap, transmobile`.
- Super admins listing all auth users also see Transmobile-only accounts (no Portal profile); don't delete or ban accounts that have no Portal profile from the Portal.

Single login (since 26/11/2026): the only login screen is the Gerenciador Transdata (repo `gerenciador-transdata`, https://gerenciador-transdata.vercel.app). This app is served inside that address under `/transdata/` (Vercel rewrite in the Gerenciador to this project), so the Supabase session in localStorage is shared with the Gerenciador, Transmobile (`/transmobile/`) and RoadMap (`/roadmap/`). Rules:
- Vite `base` is `/transdata/` and the build goes to `dist/transdata`; the router uses that basename. Links outside the router use `urlDoApp()` from `src/lib/portalAcesso.ts`; never hard-code `/`-rooted paths or `window.location.origin` + route.
- No login, signup or password pages here: without a session the app sends people to `/?voltar=<page>` (`irParaLogin`), the old `/login`, `/cadastro`, `/forgot-password` and `/reset-password` routes forward to the Gerenciador, and recovery links (`type=recovery`) are handed over in `index.html` before Supabase reads them. A session with no Portal profile shows "Sem acesso ao CS Flow".
- The origin is shared: don't unregister other service workers or delete caches/localStorage keys you don't own; name new storage keys and caches so they can't clash with the other apps.
- The old address (projetostransdata.vercel.app) only serves `endereco-antigo.html` (forwards to the same path under the Gerenciador), self-destroying `/service-worker.js` and `/sw.js`, and `/email/*` for emails already sent (generated by the `endereco-antigo` plugin in `vite.config.ts`).
- Local test of the whole portal: build this app, then `node ferramentas/portal-local.mjs` in the Gerenciador repo (http://localhost:4173).
